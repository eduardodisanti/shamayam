# Reproducibility package

Companion code for

> **Anomaly Detection and Classification as an Inverse Problem over a Quotient
> Space of Nuisance-Invariant Functional Manifolds**
> Theory and Validation on Synthetic, CWRU, and NASA IMS Bearing Data

The package is split by **what a reader must install**, not by what is
interesting. All three layers generate or use data as follows:

| Layer | Needs | Purpose |
|---|---|---|
| **A1** | numpy, scipy, scikit-learn | theory verification. Framework-free, no download, bit-exact. |
| **A2** | + TensorFlow | geometry demonstration with the **Conv1D autoencoder of the technical note**. Data still generated by the vendored simulator. |
| **B** | + the CWRU and NASA IMS archives | field reproduction. Both public but externally maintained; neither redistributed here. |

## Running it

```bash
pip install -r requirements.txt          # A1
pip install tensorflow                   # A2, optional

# 1. verify the mathematics  (fast, no framework)
python3 -m pytest tests -q -m "not slow"

# 2. regenerate every reported number  (A2 trains; expect minutes)
python3 run_all.py                       # -> results/{layer_a_results.txt,
                                         #             data.json, manifest.json}

# 3. regenerate the paper's tables, figures and inline numbers FROM that run
python3 make_tables.py                   # -> ../tables/*.tex
python3 make_figures.py                  # -> ../figures/*.pdf
python3 make_macros.py                   # -> ../tables/values.tex

# 4. the training-dependent tests, run deliberately
python3 -m pytest tests -q -m slow
```

### Nothing is transcribed by hand

`run_all.py` writes `results/data.json`, a structured record of every reported
quantity. Both the LaTeX tables and the figures are generated from that one
file and from nothing else, and the paper `\input`s the tables and includes
the figures. A regenerated run therefore propagates into the document without
anyone copying a number, which is the step at which a results section silently
goes stale.

Four consequences worth knowing:

* Each generated table carries a provenance header naming the run and seed it
  came from, and says so in the source if that run was `--quick`. A table that
  was not regenerated is visible as such.
* If `data.json` lacks a section — running `--layer a1` produces no A2 data —
  the generators emit a **visible placeholder** rather than failing or, worse,
  leaving a stale artefact in place. The document still compiles and the gap
  is obvious in the PDF.
* A partial run does **not** discard the sections it did not produce. Running
  `--layer a1` over a complete `data.json` carries the A2 sections forward and
  records them under `_carried_over` with the run they came from, so a mixed
  artefact announces itself instead of masquerading as one run.
* The numbers quoted **inline in the prose** are generated too, by
  `make_macros.py` into `tables/values.tex`, which the paper `\input`s in its
  preamble. The prose says `\satBiasHi`, not `6.43`. This was the last place a
  value could go stale unnoticed, and it did: a sentence in the saturation
  discussion outlived the operator whose detection rates it quoted. An
  undefined macro is a compile error by design — an unavailable number should
  stop the build rather than leave an old one standing.

Prose that reads well still cannot be generated mechanically, so the sentences
are written by hand; only the quantities inside them are not.

The CWRU and NASA IMS tables are **not** generated, because they come from
Layer B rather than from this run. They remain hand-written until that layer is
re-executed.

Useful variants:

```bash
python3 run_all.py --layer a1            # theory only, no framework, ~1 min
python3 run_all.py --quick               # smoke test, numbers not quotable
python3 run_all.py --extensive           # tighter Monte Carlo error
```

### The A2 training schedule

`--epochs` is a **budget, not a target**. Convergence is decided by the data:

| control | default | meaning |
|---|---|---|
| `--epochs` | 500 | upper bound; reaching it means training was *truncated* |
| `--patience` | 40 | early stopping on validation loss, best weights restored |
| `--lr-patience` | 15 | epochs on a plateau before the learning rate is halved |
| `--min-lr` | 1e-7 | annealing floor; past it, reduction cannot help |

Validation is a held-out split of the **nominal** data, so early stopping
never sees a fault and cannot leak fault information: it selects for
reconstructing nominal data, which is exactly what the one-class formulation
asks for.

The realised schedule is written into the results file, for example

```
A2 training schedule realised: 37/500 epochs, stop=early_stopping,
best val_loss=0.01079 at epoch 34, lr 1.0e-03 -> 5.0e-04 (1 reductions)
```

If `stop_reason` is `budget_exhausted` the run did **not** converge and the
file says so in band; raise `--epochs`. If it is
`early_stopping_at_lr_floor`, the learning rate was annealed all the way down
before stopping, which is the intended terminal state.

**None of the mathematical claims depend on A2 or B.** The calibration results
are operator-independent and are verified in A1 against six deliberately
dissimilar residual distributions.

### Why the Conv1D operator, and why a linear one is kept beside it

A2 uses the architecture of the technical note verbatim — 847,601 parameters,
pinned by a test — rather than a convenient substitute. The convolution is not
an implementation detail: an observation window is a delay-coordinate vector,
a phase shift acts on the reconstructed orbit as the flow itself, and
translation equivariance is therefore the inductive bias that matches the
nuisance group being quotiented out.

A PCA operator is retained as a **negative control**, because it makes the
adequacy criterion concrete. Both operators attain the calibrated coverage.
They differ by more than two orders of magnitude under the distance-proxy
probe:

On the reference run: PCA-16 accepts points at **382×** the nominal
nearest-neighbour spacing with residuals of order `1e-30` and **fails**; the
Conv1D autoencoder accepts only to **1.6×** and **passes**. The current values
are in `results/data.json` and in the generated `tables/adequacy.tex`, so this
paragraph is the only place they are quoted by hand.

The linear residual is exactly distance to a 16-dimensional subspace, so its
accepted region is a slab around that subspace rather than a tube around the
four-dimensional nominal manifold. It still detects the simulated faults at
84–100%, which is the point of keeping it: **good detection on the faults one
happens to have is not evidence that the accepted region is tight.**

### Determinism

A1 is bit-exact. A2 activates
`tf.config.experimental.enable_op_determinism()` together with
`keras.utils.set_random_seed`, so repeated runs agree exactly **within one
TensorFlow build**; this is not guaranteed across builds, versions or
backends, and op determinism costs speed. Both facts are recorded in
`results/manifest.json`.

## Layer A1 — theory verification, framework-free

Depends only on `numpy`, `scipy`, `scikit-learn` and `pytest`. Runs in about a
minute on a laptop CPU and is bit-exact under the recorded seed.

Results are identified by LaTeX label, not by number: numbering shifts as the
paper is drafted, and every label below resolves in `../mssp_draft.tex`.

| Paper claim (label) | Where it is checked |
|---|---|
| distribution-free coverage `P(r ≤ τ) = k_α/(n+1)` (`prop:coverage`) | `tests/test_coverage_exact.py` — exhaustive enumeration of all orderings, no sampling |
| minimum commissioning length `n ≥ 1/α − 1` (`cor:min_commissioning`) | `tests/test_corollaries.py` — grid over α, tightness at the boundary |
| degenerate range `1/α−1 ≤ n < 2/α−1` (`cor:degenerate_range`) | `tests/test_corollaries.py` — grid over α, plus the variance consequence |
| interpolated quantile is anti-conservative (`rem:interpolation_bias`) | `tests/test_estimators.py` — property test; Experiment 1 quantifies it |
| effect of adaptive stopping (`rem:optional_stopping`) | Experiments 1 and 2 — Experiment 2 isolates selection from sample size |
| exchangeability is testable (`rem:exchangeability_test`) | `tests/test_exchangeability.py` — size and power; Experiment 4 |
| residual as distance proxy (`ass:residual_proxy`) | `tests/test_end_to_end.py`, Experiment 5 |
| radius is asset-specific (`rem:scale_not_invariant`) | `tests/test_end_to_end.py`, Experiment 5 |
| the 49 coincidence, Sec. 9 confound | `tests/test_stopping.py` |

Section 5 adds three results about the saturation radius. Two are inherited
rather than newly implemented, which is why no new code accompanies them:

| Section 5 claim (label) | Where it is checked |
|---|---|
| consistency `R̂_p(n) → R_p` (`prop:radius_consistency`) | `tests/test_saturation.py` — bias and dispersion both contract with `n`; Experiment 6 |
| certification of the saturation radius (`cor:saturation_certification`) | `tests/test_saturation.py` — coverage on held-out nominal windows; the degenerate-range identity holds for radii too |
| finiteness of the saturation radius (`cor:finite_radius`) | analytic consequence of `prop:compactness`; checked only as a sanity condition |
| plug-in reference shrinks the radius (`rem:plugin_centroid`) | `tests/test_saturation.py` — predicted sign; Experiment 6 quantifies it |
| curve/guarantee tension (`rem:saturation_tension`) | `tests/test_saturation.py::test_radius_rises_with_n_inside_the_degenerate_range`; Experiment 6 |
| radius is not a detector (`rem:radius_not_detector`) | Experiment 6, per-regime block — a **negative** result |

### Three findings from Experiment 6 worth knowing before reading a saturation plot

1. **Inside the degenerate range the certified curve cannot flatten.** The
   radius *is* the sample maximum there, so it drifts upward with `n` (about
   +2% above `R_p` at `n=49`, +6% at `n=98`) and drops discontinuously at
   `n=99`. Apparent settling in that band is the maximum of a growing sample.
2. **The curve and the guarantee are in tension.** The interpolated estimator
   produces the familiar smooth approach to `R_p` from below — and undercovers
   at every `n`. The estimator that makes the plot look convergent is the one
   that fails to certify.
3. **The radius is a diagnostic, not a detector.** Per-regime radius ratios in
   a 2-D nominal projection are 0.98–1.04: no separation, even though the same
   simulator and nominal-only fitting give 99–100% detection under the residual
   rule in Experiment 5. A saturation plot is evidence about the sampling of
   the nominal geometry, not about regime separability.

The other descriptors of the informal criterion, entropy `H(n)` and volume
`V(n)`, are **not** implemented; only the radius is given a precise estimator
in Section 5.

The probe is a **stated adequacy criterion**, not a decoration: any candidate
residual should be held to it before use, including the operator used on real
data in Layer B, which has not yet been checked this way.

**Training budget.** `--epochs 30` is the default; the technical note uses 100
with learning-rate reduction. Short runs are flagged in the results file
because they produce unrepresentative detection rates. The adequacy probe and
the calibration results are far less sensitive to this than the detection
rates are.

### Exporting residuals for Layer-A analysis of field data

The calibration analyses operate on the one-dimensional residual streams
alone, so the field experiments can be re-analysed without retraining and
without redistributing the datasets. With the notebooks run and the models in
memory, append:

```python
import numpy as np

# CWRU: window-level residuals per operating condition
np.savez_compressed(
    "residuals_cwru.npz",
    **{f"{cond}_{regime}": np.asarray(res[regime], dtype=np.float64)
       for cond, res in field_residuals.items()
       for regime in ("healthy", "ball", "inner", "outer")})

# NASA IMS: recording-level residuals, chronological order
np.savez_compressed(
    "residuals_nasa.npz",
    **{f"b{bid}_early": np.asarray(scores, dtype=np.float64)
       for bid, scores in early_life_recording_scores.items()})
```

Roughly 12k floats in total. Adjust the inner keys to the actual dictionary
layout.

## Provenance and faithfulness

`AdaptiveOperationalRadius`, `operational_radius_convergence_trace` and
`find_convergence_index` are ported verbatim from the published notebooks,
with the estimator injected as an argument so that the two calibration
conventions can be compared on identical machinery.
`tests/test_estimators.py::test_port_reproduces_the_published_estimator_exactly`
pins the port bit-for-bit against an independent transcription, so the `A1`

## Discrepancies between the notebooks and the published text

### 1. NASA persistence rule — NO DISCREPANCY. The published run used 8 of 10

This was recorded as an open discrepancy through a full draft. It is not one,
and the record is corrected here rather than quietly deleted.

The notebook defines `PERSISTENCE_Q = 3`, `PERSISTENCE_P = 5` at module level,
and those constants are what an inspection of the file finds first. They belong
to the per-asset path. The cell that actually produces the reported
run-to-failure results defines its own:

```python
PERSISTENCE_WINDOW   = 10
PERSISTENCE_REQUIRED = 8
```

so the published lead times were computed under **eight of ten**, exactly as
the text describes. The saved cell output confirms it arithmetically:
`declaration_index = onset_index + window_size - 1`, and every bearing shows
`declaration - onset = 9` — that is `10 - 1`, which is impossible under a
five-recording window.

    Bearing 1 | persistent onset=530 | declaration=539 | lead time=74.00 h
    Bearing 2 | persistent onset=741 | declaration=750 | lead time=38.83 h
    Bearing 3 | persistent onset=887 | declaration=896 | lead time=14.50 h
    Bearing 4 | persistent onset=648 | declaration=657 | lead time=54.33 h

**The reported lead times therefore stand and require no recomputation.** The
lesson is about the audit, not the experiment: module-level constants were read
as though they governed a cell that overrides them.

The analysis that was done while believing the discrepancy was real is kept,
because it justifies the rule rather than merely recording it.
`false_declaration_probability` shows that at the attained healthy false-alarm
rate near 5% a three-of-five rule would declare a spurious departure with
probability 0.37 over a 2000-recording run, against 3.1e-07 for eight of ten.
The published choice is the defensible one; it is now defended rather than
assumed.

### 2. NASA recording-level aggregation — RESOLVED: the mean is correct

`RECORDING_SCORE_PERCENTILE = 95.0` is not a dead constant. It is used by
`aggregate_window_scores_by_recording` on the per-asset path, while
`shared_nasa_recording_scores` uses `np.mean` under a comment reading "Must
match the aggregation used in the main NASA experiment". The two paths
disagree.

**Every IMS number in the paper comes from the mean path** — the shared
representation experiment, the resampled-commissioning experiment and the
run-to-failure cell all call `shared_nasa_recording_scores`. The manuscript is
internally consistent; the inconsistency is between a reported experiment and
an unreported one.

The mean is also the right choice, for two reasons that are pinned by tests in
`tests/test_dynamics_dimension.py`.

**A 95th percentile of 17 windows is the sample maximum.** At alpha=0.05 the
feasibility floor of `cor:min_commissioning` is 19 observations, and
k_alpha = 18 > 17, so the quantile is not defined distribution-free at all.
Overlapping to 33 windows clears the floor but lands inside the degenerate
range, which extends to 39. Adopting the percentile would reproduce, inside
the reduction, the exact failure mode this package documents.

**The premise behind the percentile is false at this window length.** IMS
Experiment 2 runs at 2000 rpm with an outer-race defect frequency near 236 Hz,
so a 1200-sample window at 20 kHz spans 60 ms and contains roughly fourteen
defect impulses. The signature is in every window, not in a few. In that
regime averaging divides the nominal dispersion by sqrt(17) and leaves the
shift in the mean intact — measured contrast 15.5 against 9.3 for the
percentile. The percentile only wins when the anomaly is genuinely sparse.

Note that the choice does not affect coverage either way: the reduction enters
calibration and evaluation identically, so the radius is compared against
scores on its own scale. It affects sensitivity, and that is the ground on
which it was decided.

Neither discrepancy affects Layer A.
